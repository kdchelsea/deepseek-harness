# Agent Note: 模型请求进展独立于 Session 历史

Status: implemented

[English](2026-11-04-model-request-diagnostics.md) | 中文

## Problem

模型调用可能在收到 HTTP 响应头或部分输出后仍不结束。[内嵌流决策](2026-09-01-v2-embedded-assistant-streams.zh.md) 在尝试结算时提交正文，因此进程突然终止后可能只留下步骤开始事件。仅凭这些证据，运维人员无法区分尚未发送、等待响应头、已消费响应数据和已产生规范化输出。捕获完整协议正文还会保留诊断活性问题并不需要的提示词和生成内容。

## Decision

[请求诊断插件](../../../../packages/llm/llm-request-diagnostics/README.zh.md) 为每次模型调用管理独立、有界的 NDJSON 文件。提供方适配器通过 LLM 扩展点获取观察器；循环、Session 格式、模型上下文和重试策略保持独立。文件包含来源标识、HTTP 交换序号、状态、字节／分片计数与时间戳、进展检查点和终态。记录不包含 URL、请求头、响应头、正文、错误消息或取消原因。

每个阶段及周期检查点同步追加，使模型尝试结束前和进程终止后都能读取已写记录，但不承诺掉电持久性。正文观察跟随提供方消费者，不使用 tee 或提前读取：计数表示已消费、由 fetch 解压的字节，不代表实际网络到达。部分提供方传输不经过注入的 fetch，因此未观察到的 HTTP 交换保持未知。

现有内嵌流与[轨迹请求／响应检查](../feature/2026-09-10-trajectory-request-input.zh.md)决策仍然有效；诊断计数不替代它们的完整正文与回放保证。仅凭元数据不能重建丢失的响应，也不能成为工具已执行的证据；[有界响应前缀](2026-11-06-incremental-response-prefixes.zh.md)提供独立正文证据，不改变该记录的权威范围。

## Alternatives considered

**将每个 token 持久化为 Session 事件。** 这会恢复逐 token 的事件和存储成本，改变 Session 表示，并把运行元数据与回放权威混合。独立记录只保留进展证据，不能改变模型历史。

**等待响应捕获完成 flush。** 卡住的调用或进程强制终止可能永远无法到达结束处理。独立检查点在完成前保留有用证据。

**并行读取克隆的响应。** tee 可能先于提供方消费数据、额外缓存内容，并改变观察到的时序或取消行为。观察应位于已有的消费者驱动读取路径上。

**记录所有请求头、响应头、URL 和异常文本。** 这些值可能包含凭据、用户内容或私有端点信息。有界计数和受控机器错误码提供阶段信息，无需保留这些值。

## Consequences

少量同步写入会在阶段切换和配置的间隔处增加文件系统延迟。达到文件大小上限后，用明确的截断记录停止普通检查点，并为终态元数据预留空间；完成的文件保留到操作者删除。日志失败会通过 stderr 明确报告，并停用该观察器，不把模型结果转换成错误。插件卸载关闭文件和计时器，不取消模型调用。

headless profile 测试在等待响应头，以及不完整正文已产生规范化输出时终止真实子进程。两种情况都保留可读取的诊断前缀，不伪造完成记录。观察器测试覆盖无提前读取、字节和 Response 元数据不变、取消、大小限制、私有内容排除和生命周期清理。适配器测试保留既有请求、输出、错误和重试行为。
