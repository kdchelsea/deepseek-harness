# Agent Note: 未结束请求的有界响应前缀留存

Status: implemented

[English](2026-11-06-incremental-response-prefixes.md) | 中文

## Problem

[请求进展记录](2026-11-04-model-request-diagnostics.zh.md) 能区分等待与活跃消费，却无法揭示重复 SSE 事件或缺失的终态事件。Web 轨迹在适配器收尾时捕获响应文本；headless 没有轨迹持久化监听器，进程强制终止也无法执行该收尾逻辑。因此，未结束的请求需要在结算前留下独立的响应前缀记录。

## Decision

[请求诊断插件](../../../../packages/llm/llm-request-diagnostics/README.zh.md) 在单次调用的元数据旁管理私有响应文件。它在向提供方解析器交付已消费的 HTTP 正文字节之前追加写盘，调用内的全部 HTTP 交换共用一个字节预算。不引入 tee、第二个读取器或无界内存缓冲。元数据标识每个获准创建的文件，并记录保留字节数、截断、错误和结束观察；EOF 与模型完成仍是独立事实。

原始前缀用于诊断，不是 Session 历史或回放权威。它们可能包含敏感模型输出，因此配置支持关闭正文留存而保留进展元数据。文件不添加请求正文、认证头、URL、异常消息或取消原因。操作者负责诊断目录的保留策略和访问权限。

现有进展与[内嵌流](2026-09-01-v2-embedded-assistant-streams.zh.md)决策保持有效。响应前缀补充其证据，不把部分助手消息提交到模型上下文。独立的旧响应预览也受字节上限约束；其截断标记与传输 EOF 独立，并在 Web 轨迹检查中明确显示。

## Alternatives considered

**只在请求完成时 flush。** 持续活跃的流或 SIGKILL 可能阻止完成。增量写入在不依赖卸载清理的前提下保留已消费前缀。

**把每个解析分片持久化到 Session 历史。** 这会改变回放语义并大幅增加 Session 事件。即使提供方解析器无法产生完整工具调用，原始 HTTP 证据仍有价值。

**通过 tee 复制响应。** 独立读取改变背压，并保留额外的待处理字节。观察进度应由已有消费者决定。

## Consequences

同步写入会给已消费分片增加文件系统延迟。字节上限和元数据预留限制每次调用；进程终止可能留下不完整的最后分片或元数据行，且没有终态记录。较早的操作系统写入可在进程终止后保留，但不承诺 fsync 或掉电持久性。存储失败明确可见并被隔离，不改变模型字节或重试策略。

验证覆盖实时前缀读取、多个响应共享上限、字节精确截断、无提前读取、写入失败、取消与卸载。已发布 headless profile 的子进程场景针对两种支持的 HTTP 协议，在 SIGKILL 前后检查前缀；截断及关闭捕获均保留模型解析进展，不伪造 EOF 或完成。
